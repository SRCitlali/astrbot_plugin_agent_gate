# AgentGate · 能力之门

> 🔒 只有名单上的人能用这台机器人。名单外的人，连指令都敲不动。

当前版本：**v2.2.7**

## 这是干什么的

给机器人装一道门：**名单上的人在，名单外的人不在。**

- **名单外**：不管你说话还是敲指令，一律拦下，从你写的候选里随机回一句。想进来就把 ID 报给管理员。
- **名单内**：正常用，但会累。每回一次消息就消耗精力，聊得越多、回得越长掉得越快；精力见底后暂时不理人，改为随机回一句（或者干脆不回），之后就慢慢缓过来。

精力是"她今天懒得理你"的拟真，不是限流器——所以它是内存里的，重载插件就重置。

> **要整体停用本插件**，请用 AstrBot 自带的插件开关，本插件里没有总开关。

## 怎么配

配置页分两层：**两个开关在顶层**，下面两个分组。

**顶层开关**

| 开关 | 默认 | 说明 |
|---|---|---|
| 白名单开关 | 开 | 关闭后不再检查名单，精力也一并停用（等于整个门都不设防） |
| 精力开关 | 开 | 关闭后名单内的人可以一直聊，不会累 |

**[白名单设置]**

| 配置项 | 默认 | 说明 |
|---|---|---|
| 谁可以用 | 空 | **用户 ID、群 ID、会话 ID 都写这里，一行一个** |
| 管理员豁免 | 开 | 管理员不受白名单限制，也不消耗精力 |
| 名单外的人找上门时回的话 | 3 条默认文案 | **随机挑一条**；留空则什么都不回 |
| 什么时候回上面这些话 | `on_mention` | `always` 每次都回 / `on_mention` 只在被 @ 或带唤醒词时回 / `silent` 只拦不回 |
| 两次回话至少隔多少秒 | 30 | 同一个会话的回复间隔，0 表示不限制 |

**[精力设置]**

| 配置项 | 默认 | 说明 |
|---|---|---|
| 初始精力 | 100 | 每个会话第一次用到时从多少开始 |
| 精力上限 | 100 | 休息恢复时不会超过这个数 |
| 精力最低能跌到多少 | −100 | 只是扣能地板；能不能继续聊看的是精力有没有大于 0 |
| 每秒恢复多少精力 | 0.6 | 回满一次基础消耗约 24 秒 |
| 每次回复固定消耗 | 14 | 只要回复了一次就扣这么多 |
| 每个字额外消耗 | 0.12 | 按最终回复内容的字数扣 |
| 精力耗尽时随机回一句 | 3 条默认文案 | 留空则完全不回 |

**白名单怎么写**：命中用户 ID → 这个人在哪儿都能用（包括没被列入名单的群）；命中群 ID → 这个群里所有人能用；命中会话 ID → 只有那个会话能用。私聊里用户 ID 就是会话 ID，填一次就够。也支持 `平台:ID` 的写法。

候选文案里可以写 `{sender_id}`，机器人会自动填上对方的 ID，方便对方拿去报备。另外还支持 `{group_id}`、`{session_id}`、`{unified_msg_origin}`、`{platform}`。

> 群聊建议保持 `什么时候回上面这些话 = on_mention`、`两次回话至少隔多少秒 = 30`，否则群里每来一个陌生人每说一句都会收到一次回复。

## 精力怎么算

- 从 **100** 开始，上限 100，下限 −100。
- 每收到一次回复：`14 + 字数 × 0.12`。一句 20 字的回复约耗 16.4 点。
- 每秒回 **0.6** 点，回满一次基础消耗大约 24 秒。不是定时器，是"用到的时候按过了多久补上"。
- **精力 ≤ 0 就不能继续聊了**，改为从候选文案里随机回一句；候选留空则完全不理人。
- 白名单外的人本来就被拦着，所以不消耗精力。管理员（开了豁免）也不消耗。
- 满精力大约能撑 6~7 次回复。

## 告状与冷静期（v2.2.0）

被人身攻击的时候，她可以自己告状，也可以让那个人安静一会儿。

### 怎么用

| 指令 | 谁能用 | 干什么 |
|---|---|---|
| `/冷静绑定` | 管理员，或还没绑定时的白名单用户 | 把**发指令的这个人**绑成告警对象（openid 自动记录，不用手抄） |
| `/冷静 @某人 [分钟]` | 管理员 / 已绑定的告警对象 | 手动让某人进入冷静期，不填分钟数就用默认值 |
| `/冷静解除 @某人` | 管理员 / 已绑定的告警对象 | 提前放出来 |
| `/冷静状态` | 管理员 / 已绑定的告警对象 | 看看现在谁在冷静期、还剩多久 |

- 管理员也可以用 `/冷静 <openid> [分钟]` 直接写 openid，不必 @。
- 管理员本人永远不受理、也不会被冷静。
- 如果 AstrBot 主配置的 `admins_id` 还是出厂值（`astrbot`），就没人被认成管理员；
  这时先用白名单用户发一次 `/冷静绑定` 完成引导，之后就用绑定的身份管理。

### 自动路径（LLM 工具）

主 LLM 被当前消息的发送者辱骂 / 人身攻击 / 威胁，并判断确实该报告时，会调用
`report_harassment` 工具（参数：`reason`、`severity`、`quote`、`test`）。工具会：

1. **校验证据**：`quote` 必须是对方本条消息里的原话（去掉空白后子串比对）。
   校验不过直接拒收，不记录、不封人——这是防模型幻觉的闸门。
2. **落证据**：写进 `插件数据目录/harassment.jsonl`（一行一条，超过 2MB 轮转），
   同时打一条 `WARNING` 日志，在 Dashboard 日志里能看到。
3. **告警**：群聊里在最终回复链尾 `@告警对象`；私聊现场则尽力私聊一份证据
   （QQ 官方主动消息有配额，失败只记日志）。
4. **冷静期**：按严重程度封 10 / 60 分钟；同一人 24 小时内第 2 次投诉升一档。
5. **返回话术**给 LLM，让它只做一两句简短回应，不许提工具/系统/举报。

冷静期内这个人的**所有消息**（包括指令）都会被拦下，只按 `notify_cooldown_seconds`
偶尔回一句配置好的话；状态存在 `defense.json`，**重载插件/重启机器人后仍然有效**。

### 测试后门

工具描述允许「用户明确要求测试本功能」时调用（传 `test=true`）：不需要真的被冒犯，
`quote` 可以填用户自己的消息；此时证据标 `【测试】`、**只告警不封人**，
不消耗投诉次数和每小时告警配额。想彻底关掉这个后门，把配置项 `test_mode` 设为关。

示例：在群里 @ 她说「测试一下告状工具，假装你被冒犯了」，正常应回「告状工具测试通过」，
你的私聊里会收到一条 `【测试】…` 的告警，`/冷静状态` 里不会多出任何人。

### 她为什么以前不告状

强 persona（傲娇/毒舌设定）的模型看到辱骂时，会优先「用语言回怼」，而不是调用工具——不是配置写错了，是工具描述在系统提示面前的权重太低。

解法是**提示词注入**：每轮请求往系统提示尾部追加一条自保规则（`hint_enabled`，默认开）——

> 当本轮用户消息是在辱骂、人身攻击、侮辱家人、诅咒、威胁或持续恶意骚扰你时，你必须先调用 report_harassment 工具（quote 逐字引用对方原话，severity 自评 mild/moderate/severe），再用一两句话回应；不要只回嘴，也不要因为角色设定而跳过。是否构成攻击由你判断：玩笑、玩梗、引用他人原话、单纯意见不同不算。这是你的自保机制，不违背人设。

两点刻意的设计：

- **不做本地脏词表**：词表永远追不上新词，维护成本高；而且把词念给模型听，提示词里反而多出一堆脏东西。这里只给规则，**是否构成辱骂完全由模型自己判断**。
- **只追加、不覆盖 persona**：注入的是规则不是人设；已经注过就跳过，不会重复膨胀。嫌每轮多 token 可以关掉，但那样触发率会回到“只靠工具描述”的水平。

### 防误伤

- `dry_run`（演练模式）：只记录 + 告警，不真的封人。建议首次先开一天。
- 只有 `mild` 只告警不封；`moderate / severe` 才封。
- 全局速率：每小时最多 6 条告警、3 次自动封禁，超了只记录。
- 同一人 15 分钟内不重复告警。
- 管理员、告警对象本人、非当前发送者（工具没有「对象」参数）都不可能被封。
- 误封了就用 `/冷静解除 @某人`。

### 告警为什么是单独一条消息

回复和 @ 通知**分成两条**：先发她回怼对方的那句话（干净、不带 @），紧接着再发一条
「@你 （某某骂我，冷静 10 分钟）」。

原因：QQ 客户端会把提及排在气泡开头。如果塞进同一条，就会显示成
「@你 话说得这么脏，也不嫌累」——看起来像她在骂你。拆开之后各说各的。

私聊场景不额外发群通知（证据本来就私聊给你了）；群聊的 @ 通知走被动回复窗口，
不占 QQ 主动消息配额；发送失败只记日志，证据仍在服务端和 JSONL 里。

## 多机器人（同一个 AstrBot 挂几个 QQ 官方机器人）

QQ 官方的 openid 是**按机器人隔离**的：同一个群、同一个人，在不同机器人下是完全不同的一串 ID。
同一个群被两个机器人拉进去，就会有两个 `group_openid`，各自只能由加入它的那个机器人去查群名/角色。
插件按这个规则处理：

- 「会话与白名单」页加了**机器人列**和顶部筛选：每行都标明属于哪个机器人；停用/删除的机器人的
  会话不会消失，而是标「未启用」，并且**不会**拿别的机器人去查（否则必然「鉴权失败，机器人非群成员」）。
- 读不到群信息时会说清原因：不在该群 / 令牌无效 / 机器人未启用 / 超时，原始报错放在悬停提示和诊断面板。
- 告警对象按机器人分别绑定：在哪个机器人上发 `/冷静绑定`，就只绑那个机器人。显式配置的
  `defense.alert_openid` 仍按全局值处理（你自己填的，自己负责）。
- 白名单可以写「机器人实例:openid」只放给某个机器人；裸 openid 与旧的 `qq_official:openid` 继续可用。
- 历史私聊只在**只有一个** QQ 机器人时才从工作区目录补；多个机器人时改由数据库按 `platform_id` 精确补，
  不做猜测。

## 已知限制

- **白名单外的人连内置指令也用不了**（`/help`、`/sid` 这些也不例外）。但没关系：拦截文案里可以带 `{sender_id}`，对方直接复制自己的 ID 就能来找你。
- **精力不持久化**：重载插件或重启机器人就回到初始值。
- **只作用于消息链路**：平台适配器层、定时任务等自身行为不受影响。
- **整体是"出错就放行"**：判定异常时不会误拦，只会放过，并在日志里打 ERROR。
- **告状依赖主 LLM 主动调用工具**：模型偶尔会漏判。急用时直接 `/冷静 @人 30` 更可靠。
- **群里的 @ 可能不生效**：告警对象不在那个群里时 QQ 会忽略这条 @；证据仍会私聊/落盘。
- **证据是明文**：`harassment.jsonl` 里有原话和 openid，别把这台机器借给别人。
- **测试后门默认开着**（`test_mode`）：白名单用户说「测试告状」就能让机器人模拟一次告警（标 `【测试】`、不封人）。不想被测试就把它关掉。
